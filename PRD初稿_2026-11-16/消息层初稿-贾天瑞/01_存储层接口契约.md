# 消息层 × 存储层

会前草案。以下路径和字段由贾天瑞侧先提出，供支凌宇据此开发或反馈。存储工具名是逻辑接口，本机通过文件、函数或本地服务实现均可，保留相同读写结果和原子性。原型用 SQLite 和 HTTP 演示其中的交接流程。

| 数据 | 建议位置 | 谁写、谁读 |
|---|---|---|
| 原始消息及附件元数据 | `<workspace>/superdot/messages.sqlite3` 的 `raw_messages`、`attachments` | 消息层写入；消息层组包、执行层按引用读取。 |
| 消息包和待交接项 | 同库 `packages`、`delivery` | 消息层封存和更新交接状态；执行层按包引用读。 |
| 执行侧接管记录 | 同库 `router_acceptance` | 执行侧确定性程序写；执行侧重启时查找未处理任务。 |
| 监听配置和有效时段 | 同库 `listener_settings`、`listener_periods` | 消息层写；采集端和组包逻辑读。 |
| 用户通知 | 同库 `frontend_notifications` | 各模块写自己发现的事件；前端读、标记已读。 |
| 工单 | 执行层约定的位置 | 工单程序或 Worker 写；Router 按可见性查询。消息层只传工单引用。 |

路径由本机运行配置注入。引用是稳定字符串，业务请求不传文件系统路径。时间使用带时区的 ISO 8601，分页游标由存储生成，调用方原样送回。示例中的名称、路径和索引是设计假设。

### 原始消息和上下文

| 操作 | 示例请求 | 示例返回 |
|---|---|---|
| `saveRawMessage` | `{"source":"qq","account_id":"qq-1","conversation_id":"group-1","message_id":"msg-017","sender_id":"teacher-1","sent_at":"2026-11-17T20:30:00+08:00","text":"请按模板制作志愿活动 PPT。","reply_to_message_id":null,"attachment_refs":[{"id":"template-017"}]}` | `{"code":"OK","message_ref":{"id":"raw-017"}}` |
| `readContext` | `{"source":"qq","account_id":"qq-1","conversation_id":"group-1","before_cursor":null,"limit":10}` | `{"code":"OK","messages":[{"ref":{"id":"raw-017"},"sender_id":"teacher-1","text":"请按模板制作志愿活动 PPT。","sent_at":"2026-11-17T20:30:00+08:00","attachment_refs":[{"id":"template-017"}]}],"next_cursor":null,"gaps":[]}` |
| `readReference` | `{"kind":"attachment","ref":{"id":"template-017"}}` | `{"code":"OK","ref":{"id":"template-017"},"name":"志愿活动模板.pptx","availability":"REFERENCE_ONLY","content_ref":null}` |

1. 同一来源、账号、会话和原生消息 ID 标识一条原始消息。重复保存且内容相同返回原引用。身份相同而内容不同，返回 `CONFLICT`，保留原记录。
2. 原文入库后才粗筛。读取上下文按同一会话内的稳定顺序倒序分页，保留普通发言人的背景消息。建议每页 1 至 50 条。查不到更多记录时 `next_cursor: null`；已知无法补采的时间段放进 `gaps`。
3. 附件可以先存引用，`availability` 取 `AVAILABLE`、`REFERENCE_ONLY`、`UNAVAILABLE`。可读时提供 `content_ref`，调用方按需再读。已封包的内容保持原样，后来到达的材料作为新输入或更新事件处理。

### 封包、接管和确认

| 操作 | 示例请求 | 示例返回 |
|---|---|---|
| `saveAndEnqueuePackage` | `{"operation_id":"freeze-017","kind":"source_message","text":"请按模板制作志愿活动 PPT。","message_refs":[{"id":"raw-017"}],"context_refs":[],"attachment_refs":[{"id":"template-017"}]}` | `{"code":"QUEUED","package_ref":{"id":"pkg-017"}}` |
| `readPackage` | `{"package_ref":{"id":"pkg-017"}}` | `{"code":"OK","package":{"package_ref":{"id":"pkg-017"},"kind":"source_message","text":"请按模板制作志愿活动 PPT。","message_refs":[{"id":"raw-017"}],"context_refs":[],"attachment_refs":[{"id":"template-017"}]}}` |
| `nextPending` | `{}` | `{"code":"OK","package_ref":{"id":"pkg-017"},"state":"QUEUED"}`，或 `{"code":"NO_WORK"}` |
| `recordRouterAcceptance` | `{"package_ref":{"id":"pkg-017"}}` | `{"code":"OK","package_ref":{"id":"pkg-017"},"receipt_id":"ack-017"}` |
| `recordDelivery` | `{"package_ref":{"id":"pkg-017"},"receipt_id":"ack-017"}` | `{"code":"OK","state":"ACCEPTED","package_ref":{"id":"pkg-017"},"receipt_id":"ack-017"}` |
| `recordRetry` | `{"package_ref":{"id":"pkg-017"},"reason":"ACK_UNKNOWN"}` | `{"code":"OK","state":"RETRY_WAIT"}` |

- 封包与入队同一笔提交。包 ID 由存储生成，封包成功后正文和引用不改；交接状态另外更新。全局新任务带用户原文及操作 ID，指定合并带操作 ID、来源与目标工单，均可共用封包接口。
- 看门狗取队首，标记 `AWAITING_ACK`，用包引用唤醒执行侧。建议首版同一队列只运行一个看门狗，避免额外引入领取租约。
- 执行侧通过确定性程序将包 ID 写成可恢复的待处理任务，提交成功后才回执。同一个包只生成一个接管记录，多次通知返回原回执。执行侧另行管理任务续跑。
- 消息侧校验回执的包 ID，保存回执并标为 `ACCEPTED`，同时移出待交接集合。已接管的原包继续可读。相同回执重复写返回原结果，回执 ID 冲突返回 `CONFLICT`。
- Router 不可用或回执未知时保留原包。重启后，`QUEUED`、`AWAITING_ACK`、`RETRY_WAIT` 都能重新取到。迟到的失败记录不得把 `ACCEPTED` 降回待重试。

### 监听和通知

| 操作 | 示例请求 | 示例返回 |
|---|---|---|
| `saveListenerSettings` | `{"expected_revision":3,"operation_id":"op-025","scope":{"source":"qq","account_id":"qq-1","conversation_id":"group-1"},"enabled":true,"sender_ids":["teacher-1"]}` | `{"code":"OK","saved_revision":4,"effective_revision":3}` |
| `readEffectiveSettings` | `{"scope":{"source":"qq","account_id":"qq-1","conversation_id":"group-1"},"at":"2026-11-17T20:30:00+08:00"}` | `{"code":"OK","revision":4,"enabled":true,"sender_ids":["teacher-1"]}` |
| `recordNotification` | `{"event_id":"event-017","origin":"execution","code":"MODEL_QUOTA_EXHAUSTED","package_ref":{"id":"pkg-017"},"occurred_at":"2026-11-17T20:35:00+08:00"}` | `{"code":"OK","notification_id":"notice-017"}` |

保存配置先比较版本，冲突时返回 `CONFLICT`。采集端实际应用后记录新版本的开始时间并结束前一个时段。补采按消息发生时刻查询生效版本。通知按事件 ID 去重，允许读取和单独标记已读，已读状态不会清除故障本身。

### 原型对应关系

`server.py` 的 `submit`、`package`、`context`、`notify_router`、`dispatch` 可运行。演示库复用 `inbox` 作为封包和队列表示，并用已封包 QQ 样例模拟上下文。独立原始消息表、附件正文、监听历史有效时段和持久通知是上述正式接口草案。验证命令为 `python3 verify.py`。
