# 005 控制面板

在 DeepSeek Harness Web 的侧边栏打开 **Superagent** 来监管智能体。面板优先呈现需要人工处理的工作，其次是系统健康状况与历史。本文建立在 [000 理念](000-理念.md) 至 [004 提示词](004-提示词.md) 之上。

## 三个问题

打开面板，按顺序回答三个问题：

1. 现在有什么事需要我处理？
2. 系统是否健康，是否在做该做的事？
3. 某一项工作从触发、评估到工单的完整经过是什么？

## 标签页

标签页顺着工作流排布：**总览**、**来源**、**触发**、**评估**、**执行**与**设置**。在仓库与账号配置成功之前，总览会显示缺少什么，并链接到相应设置。

| 标签页 | 展示内容 |
| --- | --- |
| 总览 | 需要处理的工单、系统问题、最近 24 小时的活动计数，以及执行器负载。每个区块都链向对应的详情页 |
| 来源 | 来源状态、安装问题与非零计数。被过滤的触发和被丢弃的消息，与总览同样覆盖最近 24 小时 |
| 触发 | 按「已订阅」「评估中」「24 小时内有新触发」或「全部线程」筛选的线程。每个线程按触发由新到旧展示，并给出决定与订阅 |
| 评估 | 决定及其理由与命中的规则 |
| 执行 | 执行器状态、暂停处理入口，以及按「开启」「待启动」「执行中」「等待触发」「已结束」筛选的工单。工单详情展示可执行动作、授权、等待中的输入、订阅与派工 |
| 设置 | 来源、评估、执行、提示词与部署。每个分组都带自己的保存历史 |

### 阅读单条记录

被丢弃的消息链向它的工单；没有工单时链向它的线程。来源页会说明究竟是会话消失了，还是来源不再监听它。

仍由执行器持有的人工追问标为 **已送达工单**，且不附带评估。线程上也展示交回理由与仅作上下文的订阅。**重新评估**可以把该追问送交评估，也可以重试一条没有有效判定的触发：被来源过滤掉的、评估结果为 `unavailable` 的，或已投递但既无「非停止」决定、也无执行器确认的消息。

工单详情展示最初的触发、决定与理由、范围以及策略版本。派工与其他次要信息折叠在即时操作之下。输入投递失败、或工单在 `blocked`／`failed` 报告之后等待人工处理时，可用 **重试**。已结束的工单显示结果，例如 **拉取请求已合并** 或 **被人工停止**。

## 设置分组

- **来源：** 每个来源一张卡片，含开关、字段与已核验的账号事实。GitHub 还为新 Issue、拉取请求、评论以及默认分支 CI 提供「接收全部」开关。轮询与读取上限放在「高级」下。
- **评估：** 策略版本与规则，随后是 **各来源分别设置** 与评估设置。每个来源标签页内含许可名单、成员同步、准入表与机器人名单。同步在启动时以及点击 **立即同步** 时执行。准入表区分接收范围、发送者是否在名单内，以及消息是否点名智能体。评估设置用于选择接单模式、超时与研判模型。
- **执行：** worker 模型、并发数、目录根路径、准备命令与禁用命令。点击某个可用变量，会把它插入准备命令。
- **提示词：** **编辑** 可改团队小节、内置部件与技能。**完整提示词** 展示组装后的文本，并可与已保存文本或默认值对比。**历史** 列出各版本。被改过的内置部件会标为已修改且可重置；模板会列出必需的占位符。

  若升级改动了某个已被覆盖的默认值，面板把它标为 **默认值已更新**（默认内容已更新），并在团队文本上方对比新旧默认值。若旧默认值没有留下记录，则改为对比团队文本与新默认值。可选择 **保留我的文本** 或 **采用新默认值**。针对已被移除部件的覆盖项列在标签栏下方，并在下次保存时删除。
- **部署：** 启动问题与 **重新检查** 按钮、状态目录以及机器限制。已保存的限制无需重启即可生效。DeepSeek Harness 的插件管理器暴露同一页面。

## 搜索

顶部搜索可按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原始消息中缺失的飞书链接，只有在本次进程生命周期内被宿主读取过之后，才可搜索。

搜索也支持按 `#12` 之类的引用或 GitHub URL 查线程，按标题或匹配的线程查工单。

## 原则

1. **聚焦要事。** 每个元素都要回答上述三个问题之一，否则删掉。一个数字只有在会改变监管者动作时才出现。
2. **定义精确。** 各类别都有可核对的定义，彼此互斥且覆盖全部情形，工单阶段就是如此。标签说明某一行在等谁、需要什么，而不是显示内部状态码。
3. **一个概念只在一处。** 来源状态归「来源」，线程与触发归「触发」，决定归「评估」，工单归「执行」。设置按所配置的概念分组。总览汇总这些页面并链向它们，而不是另做一份详细视图。
4. **遵循领域结构。** 面板使用领域术语。内部标识只出现在折叠的详情里；能解析出名称的地方，用名称替代标识。
5. **如实呈现状态。** 计数必须等于它所链接列表的长度，任何状态都不得与其他事实相矛盾。
6. **默认安静。** 健康状态不占额外版面。问题必须可据以行动，一次性的网络错误不算。需要人工处理的行直接给出操作入口。页面说明控制在一句话，更多细节放进 (?) 提示。破坏性操作需要确认。
7. **控件一致。** 沿用 DeepSeek Harness 的设计令牌与控件行为。同一信息在整个面板里外观一致。每个设置区块只有一条保存栏，仅在存在改动、正在保存或保存失败时可见。
