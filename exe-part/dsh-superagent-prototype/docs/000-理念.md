# 000 理念

dsh-superagent 既是一套框架，也是一种与智能体协作的方式。它的核心原则是：

**尽可能少地占用人的注意力，尽可能多地交付价值。**

项目的每个部分都以它所耗费的注意力来衡量。一条消息、一次通知、一个问题、一项设置、一个面板元素、一段文档，都在消耗某个人的注意力；每一处都必须给出超过这份消耗的价值，否则就删掉。

## 由此对智能体提出的要求

- **只在被请求、或有成文规则允许时行动。** 只有直接点名智能体、且来自团队许可之人的消息才算请求：许可名单上的人，或团队开放接收请求的会话中的任何人。无人请求的工作需要一条团队写下的规则，并且起步时只记录智能体本会做什么，而不真正执行。
- **只在有人必须介入、或结果可被采用时发声。** 它对请求确认一次，并说明将做什么；工作过程中保持安静；仅在结果就绪、需要决策、或无法完成时再次发言。消息要短，并且发回提出请求的那段会话。
- **每次只提一个具体问题**，并采用结构化形式，让问题真正抵达人，而不是淹没在长篇报告里。
- **以影响而非工作量决定何时收手。** 局部改动一直做到可评审的结果；需要设计决策的改动，则带着一个明确的问题停下。
- **如实汇报。** 草稿标注为未完成，失败就报告为失败；绝不为了回避提问而绕过限制。

## 由此对设计提出的要求

- **概念要少。** 设计中只有领域概念（例如来源）及其具体实现（例如 GitHub 与飞书）。一项业务需求要么成为其中某个概念的属性，要么成为智能体遵循的提示词；设计不会为此新增概念。
- **设置要少。** 当某个值几乎适用于所有团队时，就用默认值替代设置项。团队用自然语言描述的行为属于提示词文本，不是设置项。
- **面板只呈现需要人工处理的事项。** 优先列出等待人处理的内容；健康状态不占版面。
- **文档按顺序阅读。** 每篇编号文档只依赖其之前的文档，读者永远不会遇到尚未引入的概念。

## 责任

智能体以团队每天都会看到的账号发表评论、开启拉取请求、给人发消息。它发出的每条消息都在消耗同事的注意力，而你要为此负责。智能体能做的事越多，操作者对团队负有的照看义务就越重：

- **起步时收窄范围。** 先用一份很短的许可名单，主动发现的工作只做记录。等「智能体本会怎么做」看起来正确了，再逐步放宽这两处。
- **持续调优以减少干扰。** 智能体太吵时，把提示词改得更短、更严格，或者暂停它；不要靠追加更多消息去解释这些噪音。
- **不要用它堆产出量。** 批量拉取请求、群发消息和凑数的工作，给团队带来的消耗大于收益。
- **对它说出口的话负责。** 阅读智能体以你的名义发布的内容；发现不对，就在提示词里纠正。

目标是在恰当的时机提供恰当的帮助，其余时刻什么都不做。
